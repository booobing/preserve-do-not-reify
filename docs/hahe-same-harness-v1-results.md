# HAHE를 같은 하네스로 v1 — 판정 결과 (2026-10-31)

판정 규칙·예산·seed는 `docs/charter-hahe-same-harness-v1.md` §3·§4에 **HAHE 결과 관측 전** 동결됐고, 결과를 본 뒤 바꾸지 않았다.
수치는 `outputs/hahe_same_harness_v1/judged/hahe/seed_{1..5}/{metrics.jsonl,summary.json}`,
`outputs/stare_native_encoder_v1/judged/native_hyper/seed_{1..5}/`, 판정 파일 `judgment_hahe_vs_native_hyper.json`에서 옮겼다.

## 이 문서에서 쓰는 용어

- **HAHE**(Luo et al., ACL 2023): 한정쌍 문장을 다루는 모델. 문장 전체를 하이퍼엣지로 묶은 전역 하이퍼그래프(GATv2 2층)와,
  문장 한 개를 토큰 열로 읽는 지역 Transformer(12층)를 쌓는다. 공개 코드(commit `e35e0a7b`)를 한 줄도 고치지 않고 import했고, 학습 설정은 README의 WD50K 명령 그대로다(탐색 없음).
- **같은 하네스**: `native_hyper`(Study 3)를 판정한 StarE 하네스의 데이터 행·질의·후보·채점식을 HAHE에도 똑같이 쓴다는 뜻이다.
  그래프 = train + valid 26,017문장, 평가 = test 10,594 질의(주어·목적어), 후보 = 주어·목적어로 등장한 엔티티 10,874개, 필터 = 다른 정답 제거.
  모델이 내는 점수만 다르다.
- **`native_hyper`**: 5장 인코더(역할 임베딩을 더하는 메시지 전달 층 2개)에 문장마다 하이퍼엣지 1개를 주고, StarE 디코더를 붙인 것. Study 3에서 reification과 한정쌍 제거를 5/5로 이긴 arm이다.
- **두 채점 규칙**:
  - StarE 규칙(판정용): 후보 10,874개, 순위 = `1 + argsort(argsort(−점수))[정답]`.
  - HAHE 규칙(보고만): 엔티티 18,791개 전부가 후보, 동점은 정답에 불리하게 센다. HAHE 원본 평가와 같은 방식이라, 문헌 값과 맞는지 확인하는 데 쓴다.
- **판정**: test MRR과 Hits@10, 각 arm의 마지막 epoch(`native_hyper` 401, `hahe` 300). seed마다 값이 엄격히 큰 쪽이 이긴다. 두 지표 모두 5 seed 중 4 이상을 이긴 쪽의 이름이 verdict다. 방향은 미리 정하지 않았다.

## 한 줄 결론

같은 하네스에서 **HAHE가 5장 인코더를 이겼다(J3 `hahe_wins`).** MRR과 Hits@10 모두 **5/5 seed**에서 HAHE가 높고, 차이는 MRR 0.0135, Hits@10 0.0170이다.
HAHE 규칙으로 잰 MRR 0.6778은 GLoRE 저자들의 재실행값(약 0.670)과 0.03 안에서 맞아, 이식이 문헌 값을 재현했다.
우리 인코더는 같은 프로토콜에서 HAHE보다 **아래**다. 논문의 "MAYPL과 HAHE 사이"라는 위치 문장은 이 결과로 바꾼다.

Hits@1(+0.0127)·Hits@3(+0.0156)도 5/5로 HAHE가 높다. **MR만 반대다**: HAHE의 MR이 다섯 seed 모두 더 나쁘다(평균 +54.6, 95% 구간 [+37.9, +71.2]).
판정 스크립트의 승수 줄은 MR도 "큰 쪽"을 세므로 `mr: hahe 5`는 HAHE가 다섯 번 **나빴다**는 뜻이다. HAHE는 상위권 정답을 더 많이 맞히지만, 틀리는 질의에서는 정답을 더 뒤로 보낸다.

**이식 확인 (charter §4, 판정 아님)**: HAHE 규칙 MRR 0.6778 ± 0.0017은 GLoRE 재실행값 0.670과 +0.008 차이로, 허용 폭 ±0.03 안이다. "이식이 문헌 값을 재현"으로 적는다.
필터 키에서 한정쌍 순서를 우리는 원래대로, HAHE는 정렬해서 쓰므로 HAHE 원본 평가와 완전히 같은 값은 아니다.

**사전 예측(charter §5)과 대조**:
- J3는 `hahe_wins`를 50%로 가장 높게 봤고 맞았다.
- StarE 규칙 MRR은 0.64~0.70(중앙 0.67)으로 예측했고 0.6784로 범위 안이었다(중앙보다 약간 위).
- 이식 확인은 ±0.03 안일 확률을 65%로 봤고 안에 들었다.
- "HAHE 규칙이 StarE 규칙보다 낮다"는 맞았지만, 차이는 0.0006으로 작았다.

## 해석과 주장 경계

1. **J3 — 같은 하네스에서 우리 인코더는 HAHE보다 낮다.** 데이터 행·질의·후보·채점식을 모두 같게 하고, HAHE는 공개 설정 그대로 돌렸을 때 MRR·Hits@10 모두 5/5로 HAHE가 높았다(MRR +0.0135, 95% 구간 +0.0103 ~ +0.0168).
   charter §6 읽기 규칙대로, 논문 위치 문장을 "같은 하네스에서 HAHE보다 낮다"로 바꾼다.
2. **통제 비교(J1·J2)의 결론은 바뀌지 않는다.** J1·J2는 같은 인코더에서 그래프 표현만 바꾼 비교이고, J3는 서로 다른 모델의 비교다.
   "보존이 reification보다 낫다"는 주장은 모델을 고정한 비교에서 나왔고, J3는 그 모델이 경쟁 모델로서 어디에 서는지만 알려 준다.
   우리 인코더는 통제 비교용이지 경쟁 모델이 아니라는 문장을 그대로 유지한다.
3. **이식은 믿을 만하다.** HAHE 규칙 MRR이 문헌 재실행값과 0.008 차이였고, 데이터 대응(어휘 19,071, 후보 10,874, 질의 10,594)은 테스트로 확인했다.
4. **주장하지 않는 것**:
   - HAHE가 왜 이기는지 — 파라미터 5.0배, 12층 Transformer, 학습 질의 구성이 함께 다르다. 우위가 주어 예측에 몰린 것은 관찰일 뿐이다.
   - HAHE가 우리 인코더보다 일반적으로 낫다 — 데이터셋 하나(WD50K(100))뿐이다.
   - 튜닝해도 순서가 같다 — 두 모델 모두 탐색하지 않았다. HAHE 설정은 WD50K 전체용이고, `native_hyper`는 StarE 기본값을 썼다.
   - MR에서도 HAHE가 낫다 — MR은 다섯 seed 모두 HAHE가 나쁘다.
